04 Reglas que no puedes olvidar
🔒
Jamás exponer el RUT — Ley 19.628
El RUT de operarios y proveedores se guarda en la BD internamente pero nunca aparece en ningún response de la API. En los schemas Pydantic de respuesta, el campo rut simplemente no existe. En reportes externos usar codigo_empleado.
class UsuarioRead(BaseModel): id: str nombre: str email: str codigo_empleado: str # ✅ rol: str # rut: str ← NUNCA aquí
⛔
Jefe no aprueba sus propios movimientos
Al aprobar un movimiento, verificar que movimiento.id_usuario != usuario_actual.id. Si coincide, retornar 403. Este control es de auditoría interna y es obligatorio.
if movimiento.id_usuario == current_user.id: raise HTTPException(403, "No puedes aprobar tus propios movimientos")
🧱
Trigger de inmutabilidad en movimiento
El trigger PostgreSQL bloquea UPDATE y DELETE en la tabla movimiento. Si cometiste un error, registra un movimiento de tipo correccion con id_movimiento_original. El historial nunca se toca.
tipo = "correccion" id_movimiento_original = "uuid-del-original" # El trigger rechazará cualquier UPDATE directo
📋
Campos SERNAPESCA siempre obligatorios en entradas
En el schema MovimientoCreate, cuando tipo == "entrada_proveedor" los campos numero_lote, fecha_vencimiento, nombre_proveedor, num_guia_despacho y registro_sanitario son obligatorios. Para veterinarios agregar num_receta_retenida.
@validator("numero_lote") def lote_required_for_entrada(cls, v, values): if values.get("tipo") == "entrada_proveedor": if not v: raise ValueError("Obligatorio SERNAPESCA") return v
